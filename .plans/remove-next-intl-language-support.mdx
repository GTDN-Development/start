# Remove next-intl and all language support

## Mission

Turn this repository into a clean single-language application, as if language support and the `next-intl` implementation had never existed.

This is not a "disable the language switcher" task. The final codebase must not have locale-prefixed routes, `next-intl`, `src/i18n`, locale-aware navigation wrappers, locale cookies, localized path maps, language-specific PocketBase schema fields, or test expectations that depend on `/cs` or `/en`.

## Non-negotiable constraints

- Read `AGENTS.md` and `apps/web/AGENTS.md` before editing.
- This app uses Next.js 16 and `apps/web/src/proxy.ts`; do not introduce `middleware.ts`.
- Do not edit already deployed PocketBase migrations in place. Add a new migration under `apps/pocketbase/pb_migrations`.
- Do not edit generated `apps/web/src/types/pocketbase.ts` manually. Regenerate it after the PocketBase schema migration.
- Do not replace `next-intl` with a fake translation facade, provider, registry, or compatibility layer. Use direct strings, feature-local copy constants, and explicit route helpers.
- Keep app-specific code inside `apps/web` or `apps/pocketbase`.
- Keep the final implementation direct and concrete. Small duplication is acceptable.

## Primary language decision

Before implementation, determine the primary language that should remain.

If the task that links this plan already names the primary language, use that. Otherwise inspect the repo:

- `apps/web/src/i18n/routing.ts` currently has `defaultLocale: "cs"`.
- The current E2E suite overwhelmingly uses Czech URLs such as `/cs/aplikace`, `/cs/prihlasit-se`, `/cs/ucet`, and `/cs/o/:slug/prehled`.
- Email preview props are currently Czech.

That makes Czech (`cs`) the apparent primary language. If anything contradicts this or the primary language is not obvious, ask the user exactly one blocking question:

> What primary language should remain after removing language support, and should the public URLs keep the Czech slugs or use the English/internal route names?

Record the decision in your notes before editing:


Use `apps/web/messages/<PRIMARY_LANGUAGE>.json` as the source copy while converting translations. Delete the message files by the end of the task.

### 7. Convert translations to static primary-language copy

Use `apps/web/messages/<PRIMARY_LANGUAGE>.json` as the source of truth during conversion.

Rules:

- Remove every `useTranslations`, `getTranslations`, and `createTranslator` import.
- Do not keep a generic `t()` helper that mimics `next-intl`.
- Prefer hardcoded strings directly in JSX/markup for ordinary one-off UI copy such as labels, button text, CTA text, headings, helper text, and short descriptions. For example, replace `t("hero.cta.learnMore")` with `Learn more` directly in the component.
- Do not move text into JSON files, message objects, or copy registries just because it used to be translated. The goal is to make the project simpler to edit after language support is gone.
- Use constants or local data objects only when they are structurally useful: repeated copy, long legal/email blocks, metadata reused in multiple places, arrays that are mapped over, option lists, navigation/menu data, pricing cards, FAQ items, or plural/interpolated formatting helpers.

- Convert interpolation explicitly with template literals or small named functions.
- Convert `t.rich(...)` into normal JSX.
- Convert plural/ICU messages into explicit functions:

```ts
function formatAttachmentSummary(count: number) {
  return count === 1 ? "1 attachment" : `${count} attachments`;
```

- Remove "language switcher" and "locale switcher" copy entirely.

```js
function deleteNonPrimaryPosts(app) {
  const nonPrimaryPosts = app.findRecordsByFilter(
    "posts",
    `locale != "${PRIMARY_LANGUAGE}" && locale != ""`,
    "",
    0,
    0
  );

  for (const post of nonPrimaryPosts) {
    app.delete(post);
  }
}

function convertLayoutBannerLanguageFields(app) {
  const collection = app.findCollectionByNameOrId("layout_banners");
  const suffix = PRIMARY_LANGUAGE === "en" ? "en" : "cs";
  const selectedNames = new Set([`title_${suffix}`, `body_${suffix}`, `cta_label_${suffix}`]);
  const languageFieldNames = new Set([
    "title_cs",
    "title_en",
    "body_cs",
    "body_en",
    "cta_label_cs",
    "cta_label_en",
  ]);

  renameCollectionField(collection, `title_${suffix}`, "title");
  renameCollectionField(collection, `body_${suffix}`, "body");
  renameCollectionField(collection, `cta_label_${suffix}`, "cta_label");

  collection.fields = collection.fields.filter((field) => {
    return selectedNames.has(field.name) || !languageFieldNames.has(field.name);
  });

  app.save(collection);
}

function removeCollectionFields(app, collectionName, fieldNames) {
  const collection = app.findCollectionByNameOrId(collectionName);
  const names = new Set(fieldNames);

  collection.fields = collection.fields.filter((field) => !names.has(field.name));

  app.save(collection);
}

function renameCollectionField(collection, fromName, toName) {
  const field = collection.fields.find((item) => item.name === fromName);

  if (field) {
    field.name = toName;
  }
}
```
